# Decision matrix: the 18 phone defects and two formula-track items

This matrix reconciles the authoritative inventory in [device-defect-inventory.md](device-defect-inventory.md), not the stale desktop-era Section 11 in `research.md`. Sections 3–10 of `research.md` remain the governing architecture research for Q1–Q8.

The operator-settled constraints used here are: native Obsidian menus are being replaced by plugin-owned menus; the formula editor has no AI prompt bar; and wrap-off means uniform row height. Those choices are recorded as decisions below rather than reopened as questions.

## DEPENDENCY ORDER

1. Set Q1 presentation modes and Q2 layer/safe-area ownership first. Items 4–6 establish the sheet geometry and stacking contract; items 1–3, 7, 9–10, and 15 depend on it. Item 6 is specifically blocked from a completion claim until a real status-bar device check settles whether the reported collision exists.
2. Set the Q5 touch predicate and phone geometry subscription next. Items 2, 3, 9, and 10 need one canonical phone decision; item 10 also depends on the existing FAB inset fix remaining intact, rather than introducing a second independent inset calculation.
3. Implement the Q3 surface taxonomy and Q6 plugin-owned menu contract. Item 3 is blocked until Q1/Q3 say which surfaces are sheets versus full/near-full workbenches; item 8 is blocked until the owned flat/hierarchical menu API exists. Item 19 follows Q3 and should consume the Q8 output-format control if that control is exposed in the workbench.
4. Implement Q4 row geometry as a shared contract: item 13 precedes item 14. The table's existing `RowDensity` and per-column wrap behavior are the source baseline; the list must consume the resulting policy rather than inventing another one.
5. Set Q7 calendar data/presentation boundaries, then implement item 17's key, item 16's backlog chips, and item 18's compact month surface. Item 18 is blocked on the decision to reuse the mini calendar's index/state/keyboard model while owning phone markup.
6. Set Q8's semantic format descriptor and formatter before item 20's formula output controls and item 11's footer output. Item 11 is blocked on whether “currency configuration” means the current `type:"currency"` (currently EUR-oriented) or a new currency/locale descriptor; item 20 is blocked on percent semantics and rounding rules.
7. Apply the surface-specific decisions and run device/visual validation across the affected flows. Items 2, 6, 9, 10, 14, 15, 16, 18, and 19 retain UNKNOWN device or visual outcomes even where their source causes are confirmed.

## COLLISION RISK

`styles.css` is one 19,102-line file (`wc -l styles.css`), not a set of independently owned style modules. The screenshot harness fingerprints `styles.css` for every manifest entry: there are 196 entries, and each entry includes `styles.css` in `sourceHashes`. Any style edit therefore invalidates the source fingerprint for all 196 screenshot captures and must be authored and verified through one ordered CSS lane.

The planned styles.css-touching items are 1–10, 12–16, 18, and 19: peek/sheet presentation, layers, safe areas, shared sheet vocabulary, menus, FAB geometry, footer typography, row/list geometry, board pagination, backlog chips, calendar layout, and formula workbench layout. These items can be researched or implemented in separate source/data branches, but their CSS edits cannot be authored in parallel in the same file without serialized ownership and a complete screenshot re-capture/verification pass.

Items 11 and 20 are primarily semantic data/formatter contracts and item 17 is localization; they do not inherently require styles.css changes. If item 20 adds new formula controls that cannot use existing control styles, it joins the serialized CSS lane. The renderer/style boundary must be decided before parallel implementation.

Evidence: `tools/screenshots/README.md:12-28` explains shipped-style rendering, source fingerprints, and per-scenario captures; `tools/screenshots/README.md:57-59` identifies the manifest; `screenshots/manifest.json:2-3849` contains the 196 scenario entries and their `styles.css` source hashes; `tools/screenshots/capture.mjs:119-127` fingerprints source files and `tools/screenshots/capture.mjs:195-205` records `styles.css` per entry; `tools/screenshots/verify.mjs:68-93` compares those hashes; `src/views/CODE.md:16-18` documents the renderer-to-styles.css screenshot boundary.

## DISPUTED

- **Item 2 is mis-framed against the current source.** The properties path currently creates `.db-column-manager` and calls the shared positioning helper; the phone predicate returns sheet mode. Keep the inventory row because the reported device behavior may belong to another affordance or an older build, but do not “fix” a centered modal until the actual device path is identified. Evidence: `src/views/column-manager-renderer.ts:54-136`, `src/views/popover-position.ts:259-287`.
- **Item 6 is not source-confirmed as a visible defect.** The source confirms bottom-safe-area handling but does not prove a status-bar collision. It remains a device-validation item, not a license to add arbitrary top padding. Evidence: `styles.css:139-167`, `styles.css:16975-16993`, `src/views/popover-position.ts:270-275`.
- **Item 10 must not reintroduce the already-fixed base FAB inset.** The inventory explicitly records that earlier fix as a ruled-out non-defect. The remaining source-supported question is synchronization when geometry changes, which needs device validation. Evidence: `device-defect-inventory.md:70`, `src/views/toolbar-renderer.ts:2230-2249`, `src/data/touch-environment.ts:57-67`.
- **Item 14 is partly already mitigated in source.** The late phone CSS constrains list widths, metadata, and field wrapping, so the broad “content escapes frame” claim is not wholly current. The missing list density contract and device-level label/value behavior keep the item in scope. Evidence: `styles.css:17699-17727`, `src/views/list-renderer.ts:120-132`.
- **The three inventory exclusions remain correctly ruled out.** Bottom-flush sheet content is covered by the existing bottom safe-area padding; table right-edge chip clipping is the intended horizontal-scroll behavior; and the original FAB inset fix should not be repeated. Evidence: `device-defect-inventory.md:64-70`, `styles.css:153-157`, `styles.css:18966-18994`.
- **Item 11's “column currency config” is not yet a current-branch fact.** The current type exposes `type:"currency"`, while the existing formatter is EUR-oriented and no currency-code field was found in the inspected `ColumnDef`. Treat configurable currency as a Q8 contract decision, not as an existing property to wire through blindly. Evidence: `src/data/types.ts:79-104`, `src/data/euro-format.ts:17-50`, `src/views/table-footer-renderer.ts:201-217`.
- **Item 19's AI prompt is intentionally disputed as a target, not as a defect.** The current source does create the AI prompt action, but the operator has explicitly decided that the formula editor gets no AI prompt bar. Remove it from the target design rather than preserving it for parity. Evidence: `src/views/modals/formula-modal.ts:446-458`, `device-defect-inventory.md:59`.
