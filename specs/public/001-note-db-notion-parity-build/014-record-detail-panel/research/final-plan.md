# Final Plan: Record Detail Panel / Hover-Open UX
> Reviewed & optimized build plan, from a fresh Grok 4.6 (xhigh-fast) review of this phase's rewritten spec/plan/tasks/checklist plus its synthesis and research.

## Review — strengths, gaps, risks

**Solid.** This is polish, not a new engine. `RowData` (`types.ts:113-119`) plus `getColumnValue` (`ColumnDisplay.ts:63`) already hydrate the panel. Title-cell landmine is correctly named: the `<a>` already navigates (`CellRenderer.ts:126-129`) and already feeds Page Preview via `markNoteHoverLink` (`CellRenderer.ts:124`; `HoverLinkPreview.ts:8-17`). Insertion point is correctly **not** `setupRowInteractions` (`DatabaseView.ts:7529-7531`): `setupRow` runs at `TableRenderer.ts:468` before cells exist at `:495-505`. `renderCell` after `cellRenderer.renderCell` (`DatabaseView.ts:7840-7848`) is the real seam. Toolbar restyle is correctly forbidden (GoodBases trap). Display-only / no `DataSource` import is the right iCloud fence. Table-only keeps the call-site budget.

**The plan is named after a module that already exists.** `src/views/RecordDetailPanel.ts` is a live ~450-line **editable** calendar/timeline overlay. Exports already include `openRecordDetailPanel`, `closeRecordDetailPanel`, `refreshRecordDetailPanel`, `getOpenRecordDetailPath` (`RecordDetailPanel.ts:84-104`). `DatabaseView.ts:143` already imports them. Hosts: `DatabaseView.openRecordDetailPanel` (`:10418-10440`), `CalendarRenderer.ts:1402-1403`, `CalendarTimelineRenderer.ts:456-457`, `EmbeddedDatabaseRenderer.ts:57-61`. Overlay list already matches `.db-record-detail-panel` (`DatabaseView.ts:834`); `closeActiveOverlays` already calls `closeRecordDetailPanel()` (`:864`); `refresh()` already syncs it (`:10483-10488`). Creating `src/data/RecordDetailPanel.ts` with the same export names is a compile-time and runtime collision. Research never found this file; synthesis inherited that hole.

**EuroFormat folder cargo-cult.** `EuroFormat.ts:1-42` is pure number formatters with **no DOM, no `App`, no `Scope`**. The planned module mounts nodes, pushes keymap, and wants `renderRecordIcon` (`RecordIconRenderer.ts:18` — signature is `(parent, token, options)`, not `(parent, row, config)`), `getVisibleColumns`, and `PopoverPosition`. Putting that in `src/data/` either (a) imports `src/views/` (the isolation rule the plan cites) or (b) injects so many deps the “pure module” is fiction. The isolation pattern is “one new file + few hunks”, not “must live under `src/data/`”.

**Wrong citations / wrong hidden-set math.** `styles.css:4032` is `.db-table-wrap`, not the container. The container is `styles.css:63-125` (`position: relative; overflow: auto`). `TableRenderer.ts:24` is the **actions interface** (`getVisibleColumns(config, rows)`). The real function is `getVisibleColumns` in `src/data/ColumnConfig.ts:77-101` and it takes **four** arguments: `(config, rows, state, pendingShowColumns)`. It subtracts both `state.hiddenColumns` and auto-hidden empty columns. Plan text `config.columns minus getVisibleColumns` is invalid: `ViewConfig` has `schema.columns`, `columnOrder`, and `hiddenColumns?: string[]` (`types.ts:351-356`), not `.columns`. Hidden group = `getColumnsInOrder(config)` (`ColumnConfig.ts:64`) minus that visible set.

**Missing call site — stale DOM.** Spec §8 / CHK-069 require close-or-rebuild on `renderTable`. The plan’s two `DatabaseView` hunks (`renderCell`, `handleDatabaseKeydown`) never touch `refresh()` `:10483-10488` or `closeActiveOverlays` `:864`. A peek mounted from `renderCell` becomes an orphan after the next refresh. That is a ship blocker, not polish.

**Reuse of the calendar panel is the wrong cheap path.** It already lists visible fields, has a singleton, Esc, outside-click, and refresh. It also **edits in place** (`RecordDetailPanel.ts:257-263`), calls `actions.openRow` (`:179-183` → `dataSource.openNote` at `DatabaseView.ts:10434`), positions with `positionToolbarPopover` (`:198` — the geometry 014 forbids), does **not** dismiss on scroll (`:210-211`), has **no hidden group**, and truncates values (`styles.css:7592-7597`) which violates “long values wrap”. Wiring table OPEN to it would accidentally ship 015 write-back and fight 014’s side-peek IA.

**Effort is wrong.** 2.5h / S ignores coexistence, title-cell vs Page Preview, hidden-set math, refresh/overlay hunks, and CSS that must not reuse `.db-record-detail-*`. This is **M (~6h)**.

**Scope vs keyboard.** Plan wants a pushed Obsidian `Scope`. `DatabaseView` already owns `this.scope` and registers `Escape` → `handleInlineEditorEscape` (`:1202-1213`). The calendar panel already wins Esc with **document capture** (`RecordDetailPanel.ts:136-147, 209`). Copy that; do not push a second Scope. `formatFieldTooltipValue` lives in `views/FieldTooltip.ts:3` — stringify with `src/data/Stringify.ts:1` from a data helper, or inject from the view module.

**Title-hidden fallback is underspecified.** `db-title-cell` is only added when `file.name` is painted (`CellRenderer.ts:117-118`). If the title column is hidden, `col.key === "file.name"` never runs. Attach on the first visible data column (`getVisibleColumns(...)[0]`) from the **same** `renderCell` hunk, as Scenario 5 requires.

## Optimizations

1. **Do not create `src/data/RecordDetailPanel.ts`.** New module: `src/views/TableRecordPeek.ts` with distinct exports: `attachTitleOpenAffordance`, `openTableRecordPeek`, `closeTableRecordPeek`, `syncTableRecordPeek`. Leave `src/views/RecordDetailPanel.ts` untouched.
2. **Do not reuse `.db-record-detail-panel` CSS.** New classes (`db-record-peek-panel`, `db-record-open-btn`, `db-record-peek-field`). Existing field rules truncate and set `cursor: pointer` (`styles.css:7543-7618`).
3. **CSS-docked side-peek, not PopoverPosition.** Container is already `position: relative; overflow: auto` (`styles.css:121-125`). Dock with `position: absolute; top: 0; right: 0; bottom: 0; width: min(360px, 100%)` under `.note-database-container`. Skip `getVisiblePopoverBounds` / flip / `positionToolbarPopover`. Phone becomes full-width for free. Dismiss on container `scroll` (spec default) so the panel cannot detach inside an `overflow: auto` box.
4. **Phone OPEN is CSS-only.** `body.is-phone .note-database-container .db-record-open-btn { opacity: 1 }` plus the row-hover rule copied from `styles.css:770`. No `isPhoneLayout()` JS, no `MouseEvent`-only path.
5. **Esc = document capture**, same pattern as `RecordDetailPanel.ts:136-147`. Pass `returnFocus` to restore `td[data-note-database-row-path][data-note-database-column-key][tabindex="0"]` (`DatabaseView.ts:4197`).
6. **Hidden set from `ColumnConfig`, not invented `config.columns`.** Visible = `getVisibleColumns(config, rows, this.vs(), this.pendingShowColumns)` (`ColumnConfig.ts:77-101`). Hidden = `getColumnsInOrder(config)` (`:64`) minus that set, skip `file.name`, omit empty readonly/derived values. Reveal control only if that hidden list is non-empty.
7. **Inject view callbacks; never import `DataSource`.** `renderRecordIcon: (parent, row, config) => this.renderRowRecordIcon(...)` (not the token-level `RecordIconRenderer.ts:18` export). Stringify with `stringifyValue` (`Stringify.ts:1`). No `editCell`, no `openRow`.
8. **Third DatabaseView hunk is mandatory:** overlay selector + `closeActiveOverlays` + `refresh` sync. Count **one host file, three hunks**, plus `styles.css`. Do not pretend refresh is free.
9. **i18n is missing from the current tasks.** Add `panel.open`, `panel.noProperties`, `panel.hiddenProperties` × three locales. Hard-coded `"OPEN"` breaks zh-CN/zh-TW.
10. **Cut board/gallery, markdown body, Anytype `local` group, Anytype `Storage.setToggle`.** Unchanged.

## Risks & open decisions

- **Module name / location.** Default: **`src/views/TableRecordPeek.ts`**, not `src/data/RecordDetailPanel.ts`. The calendar module already owns that name and those exports (`RecordDetailPanel.ts:84-104`; `DatabaseView.ts:143`). Isolation = new file + few hunks (`EuroFormat.ts:1-42`), not a fake `src/data/` DOM module.
- **Reuse calendar panel vs sibling peek.** Default: **sibling, display-only.** Reusing `openRecordDetailPanel` ships `editCell` write-back (015), `openNote` navigation, toolbar-popover geometry, truncation CSS, and no hidden group — it fails REQ-001/002 and NFR-R01.
- **Side-peek vs Modal.** Default: **CSS-docked side-peek** (`aria-modal="false"`). Container is `overflow: auto` (`styles.css:121-125`); dismiss-on-scroll is the detach prevention. Switch to `Modal` only if the finance-vault layout cannot tolerate the dock.
- **Grid scroll: dismiss vs follow.** Default: **dismiss** (spec Q2). Follow-on-scroll needs `position: sticky`/`fixed` + scroll-sync; that is a later packet.
- **Keyboard.** Default: **visible button + Mod+Enter**; bare Enter stays inline edit (`DatabaseView.ts:1523-1526`). Esc via document capture, not a pushed `Scope` (avoids fighting `:1213`).
- **Hidden-group persistence.** Default: **in-memory CSS** for the panel instance. Do not write Anytype `Storage.setToggle` into the note or view def (iCloud).
- **Empty hidden values.** Default: **omit** empty readonly/derived rows; still show the group if any non-empty hidden property exists.
- **Board / gallery / body preview.** Default: **out.** Extra view hosts blow the budget; body/write-back is 015.
- **Title click still opens the note.** Default: **yes.** OPEN is peek; do not reroute `openRow` (`:7545-7548`) or patch `patchToolbarNew`.
- **z-index vs calendar panel.** Default: peek at 998, calendar detail at 999 (`styles.css:7544`). They should not be open together; refresh/closeActiveOverlays is the backstop.
- **Effort override.** Default: treat the phase as **M**, not the plan’s 2.5h S. The calendar coexistence and refresh hunk are not optional.
