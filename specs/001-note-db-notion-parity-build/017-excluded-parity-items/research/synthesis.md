# Synthesis: Excluded parity items
> One-line: ranked Notion-parity enrichment for this feature, synthesized by Grok 4.6 (xhigh-fast) from the phase's 10 research iterations. Evidence trail: research.md.

## Verdict

Do **not** build any of the five excluded items. This phase is a decision record, not a capability: the fork already covers the recoverable Notion surfaces (`Clients` as a relation, markdown `textRenderMode`, vault-local files, hover-open in phase 014), and the remaining gaps are either platform-blocked (no Obsidian user directory) or actively harmful (CDN fetch, swapping the renderer). Keep the set closed until Obsidian exposes a plugin-visible user/identity model; the single biggest risk is a later owner reading “not built” as “still TODO” and shipping a home-grown people/`me()` store or a Notion CDN downloader into an iCloud vault.

## Ranked backlog

1. **`style()` / `unstyle()` formula output** — Notion formulas emit a styled-string type (`b`/`u`/`i`/`c`/`s` plus eight text colors and eight `*_background` colors) ([formula-syntax](https://www.notion.com/help/formula-syntax)); the fork’s markdown mode already covers bold/italic/strike/highlight/code/links (`src/data/InlineMarkdown.ts:8-9`, `src/views/CellRenderer.ts:212-228`) and computed outputs are only `number | text | date | datetime | checkbox` (`src/data/types.ts:106`). Feasibility: **hard** (new value type + serializer + markdown-escaping; underline/colors still unparsed). Fork files if forced: `src/data/types.ts`, `src/data/BaseExpression.ts`, `src/data/Stringify.ts`, `src/data/ComputedSync.ts`, `src/data/InlineMarkdown.ts`, `src/views/CellRenderer.ts`. Effort: **L**. Build-order: none; not identity-gated, still skip — AppFlowy grid cells are plain `TextField`s and Anytype dataview cells carry no markdown styling (`anytype-ts/src/ts/component/block/dataview/view/grid/body/cell.tsx:38,45`). Citation: `src/data/types.ts:106` + [Notion formula-syntax](https://www.notion.com/help/formula-syntax).

2. **person / people property** — Notion `people` is an array of workspace user objects (`id`), with `created_by` / `last_edited_by` and a formula `Person` type (`name()` / `email()` / `id()`) ([property-object](https://developers.notion.com/reference/property-object)). The fork has relation-to-records only (`RelationConfig.targetDatabaseId`, wikilinks in frontmatter; `src/data/types.ts:34-37,50,67-68`) and zero `Clients`/person types in plugin code. Feasibility: **blocked** until Obsidian ships a user directory. Fork files if the trigger fires: `src/data/types.ts` (`ColumnDef.type`), relation picker / `src/views/CellRenderer.ts`. Effort: **L**. Build-order: first of the identity pair; stand-in today is a vault `Clients` relation. Citation: AppFlowy `FieldType` has Relation/CreatedTime/LastEditedTime and **no** Person (`appflowy/frontend/rust-lib/flowy-database2/src/entities/field_entities.rs:427-444`); Anytype people are `ObjectLayout.Human` / `Participant` plus `RelationType.Object` (`anytype-ts/src/ts/interface/object.ts:1-51`).

3. **`me()` / “Me” filter token** — Notion `me()` and Person-filter “Me” expand to the authenticated workspace user. Feasibility: **blocked**; depends on item 2. Fork files if the trigger fires: formula tokenizer/evaluator (`src/data/FormulaTokenizer.ts`, `src/data/BaseExpression.ts`) plus any filter UI. Effort: **M** after a real person type exists, **L** if invented as a settings-stored id. Build-order: after person/people; never first. Citation: Obsidian `App` exposes `vault` / `workspace` / `lastEvent` (pointer event, not identity) and no `user`/`account`/`profile` ([obsidian.d.ts `App`](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)); identity APIs remain unshipped ([2022 forum](https://forum.obsidian.md/t/how-do-i-access-users-obsidian-account-info-for-my-plugin/34923), [June 2026 request](https://forum.obsidian.md/t/expose-user-identity-for-sync-login/86637)). Anytype “me” is `U.Space.getProfile()` / `Participant` (`anytype-ts/src/ts/component/page/main/settings/space/share.tsx:18,26,61`).

4. **Fetching Notion file CDN URLs** — Notion-hosted `type: "file"` URLs are **temporary, valid 1 hour**, and the API says not to cache them ([file-object](https://developers.notion.com/reference/file-object)); `external` URLs never expire. Feasibility: **blocked** (product ruling, not missing code). Fork files: none in this phase; phase `012-files-column` already forbids fetch/proxy (`012-files-column/spec.md:66,82`). Effort: **L** and negative-value if forced. Build-order: never; files stay vault-local wikilinks. Citation: AppFlowy `FileUploadTypePB.NetworkFile = 1` maps to external (display-only) images (`appflowy/.../file_entities.rs:6-13`, `media_cell_editor.dart:217-223`); Anytype downloads only on explicit user gesture (`anytype-ts/src/ts/lib/action.ts:304-334`).

5. **Adopting GoodBases as the table renderer** — Gap is Notion-like chrome (hover OPEN, pills), not missing engines. GoodBases is a Bases view: “only the look changes”; no own formulas (Bases `formula.*` read-only), no rollups, footers listed as “Calculated footers (next)” ([GoodBases](https://github.com/FrancescoUmberto/GoodBases)). Feasibility: **blocked** — adoption replaces the fork’s 12 column types, 7 views, two formula syntaxes, and `count|sum|avg|list` rollups (`src/data/types.ts:50,106-108`). Fork files: do **not** retarget `src/views/*`. Effort: **L** rewrite. Build-order: never as renderer; hover-open already scoped to `014-record-detail-panel` (`014-record-detail-panel/spec.md:62,75`, REQ-003 toolbar trap). Citation: [GoodBases README](https://github.com/FrancescoUmberto/GoodBases) + `014-record-detail-panel/spec.md:62,75`.

## Recommended build (locked design)

**Ship the ruling, not a module.** Core algorithm: treat the five items as closed; resolve “people” as a relation column to a Clients (or equivalent) database of notes; render styled text only via per-column `textRenderMode: "markdown"`; keep files as vault wikilinks; keep GoodBases as a chrome reference already mined into 014. No new `src/` file, no call-site edit, no CSS — matching `spec.md` “Files to Change: (none in the plugin fork)” and `plan.md` “0 hours of fork work.”

EuroFormat remains the **reopen contract**, not this wave’s diff. `src/data/EuroFormat.ts:1-42` is a 42-line isolated override (“Kept in one module so it stays a small, rebasable diff”), consumed at `src/views/CellRenderer.ts:13,198,2576` and `src/views/SummaryRenderer.ts:7,556`. Phase 014 REQ-004 locks the same shape: one module under `src/data/` + 1–3 call-site edits (`014-record-detail-panel/spec.md:116`).

If the identity trigger ever fires, the reserved EuroFormat-shaped build is **`src/data/PersonIdentity.ts`** (map a plugin-visible user id onto the existing relation/wikilink value model — do not add a parallel directory) with at most three call sites: (1) formula evaluation (`src/data/BaseExpression.ts` / tokenizer) for `me()`, (2) `src/views/CellRenderer.ts` for people-as-relation pills, (3) the filter path for a “Me” token. A forced `style()` build would be a separate module **`src/data/FormulaStyle.ts`** at evaluator + `src/data/Stringify.ts` + `src/views/CellRenderer.ts` — not recommended; default computed sync is already `"display-only"` (`src/data/ComputedSync.ts:13,42-44`).

## Edge cases & mobile/iCloud safety

- **Styled formula write-back:** `stringifyValue` has no rich-text branch and JSON-stringifies objects (`src/data/Stringify.ts:1-14`). `ComputedSyncMode` includes `"automatic"` (`src/data/types.ts:111`, `src/data/ComputedSync.ts:42-44`); persisting `**` / `==` into YAML then re-rendering under `textRenderMode: "markdown"` double-parses markup. Underline and per-argument colors cannot render even if stored (`src/data/InlineMarkdown.ts:8-9`).
- **Home-grown `me()`:** a settings-stored id is per-vault, not per-viewer. The same iCloud vault on two devices (or two people in one vault) would disagree; Obsidian plugins cannot read Sync account identity.
- **CDN copy:** download → iCloud re-upload (double transfer) while the Notion URL rotates hourly, so the vault copy is stale by design ([file-object](https://developers.notion.com/reference/file-object), `012-files-column/spec.md:66`). Offline then serves frozen bytes.
- **GoodBases swap:** loses formulas, rollups, footers, and the note-database column model; 014 already recorded the toolbar-restyle revert (`014-record-detail-panel/spec.md:62`).
- **Mobile:** `src/views` has no `pointerType` / `touchstart` / hover-mobile handling; GoodBases-style OPEN is desktop hover. Any future chrome must follow 014 REQ-005: no desktop-only APIs, touch/tap fallback, **no writes** (`014-record-detail-panel/spec.md:117`). Rollups are already display-only and never written to frontmatter (`src/data/types.ts:69-70`).

This phase is iCloud- and mobile-safe because it is **display-only by omission**: no network fetch, no new frontmatter fields, no renderer replacement, no identity blob in the vault.

## Open questions / operator decisions

1. **Revisit trigger (REQ-003):** reopen person/people and `me()` only when Obsidian exposes a plugin-visible user/identity object, not for Notion parity alone. **Default: keep closed.** Accounts for Sync/Publish are billing-level and not a directory ([Stitchflow Obsidian API](https://www.stitchflow.com/user-management/obsidian/api)).
2. **Home-grown vault identity** (settings id, per-device name, “first note titled Me”): **Default: reject.** Unowned data, cross-device split, no viewer in shared vaults — the spec’s stated risk.
3. **`style()` overlap boundary:** markdown mode is ~bold/italic/strike/code/highlight, not underline or formula colors. **Default: still excluded.** Residual gap is new formula surface, not missing cell rendering (peers do not style grid cells).
4. **CDN / GoodBases:** **Default: never reopen**, even after an identity API. Files stay vault-local (`012-files-column/spec.md:82`); take only hover-open (already in 014), never the GoodBases renderer.
5. **People modeling in the vault:** **Default: `Clients` (or equivalent) relation column** to note records — the AppFlowy/Anytype pattern (`FieldType::Relation = 10`; `RelationType.Object` + Human layout). No plugin type named Person.
