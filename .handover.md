## What was RED, and what was not

1. **The per-view title-field picker already existed and was already reachable on phone**
   (`ViewConfig.titleField`, `board-card-properties-panel.ts`'s Title row jump affordance to
   `view-config-panel-renderer.ts`'s general-section dropdown). Confirmed by reading source and by
   the existing `panel-view-config` live-harness scenario. **Not red.**
2. **A currency-typed `titleField`'s format routing was already correct in production** — the
   `board-title-currency-column` scenario I added to `tools/live/render-assertion-harness.ts` mounts
   the real `BoardRenderer` with a currency column as `titleField` and passed on the FIRST run,
   before any code change. **D1 was an evidence gap, not a behavior gap** — the earlier fixture
   captures happened to be right.
3. **The operator's actual defect — a numeric file name with no format — was real and unbuilt.**
   `resolveTitleFieldDisplay`'s file-title branch (`titleField` unset/`file.name`) had no format
   option at all; `grep -rn "titleFormat" src` returned nothing. **Confirmed red** via new unit
   tests (`title-field-display.test.ts`) and panel tests (`view-config-panel-renderer.test.ts`),
   both failing against the unmodified tree.
4. **A second, deeper red, found only by driving production**: once the file-name `titleFormat`
   field existed and its unit tests passed, the board card still showed the raw file name.
   `board-renderer.ts`'s `getReferenceRowTitle` special-cased `title.isFileTitle` to read
   `row.file.basename` directly instead of `title.text` — a shortcut that predates this leg,
   harmless while the two were always identical, silently wrong the moment `titleFormat` made them
   diverge. No unit test could have caught this (they call the resolver directly); no fixture-based
   screenshot could have caught it either (a hand-written fixture never calls
   `getReferenceRowTitle`). Confirmed red on the real `board-title-format-numeric-filename` live
   scenario, green after the fix.
5. **A third red, found by reading the persistence layer rather than any renderer.** `titleField`
   is read/written at four separate sites in `src/data/data-source.ts` (the current views-array
   parse, the legacy flat-frontmatter parse, `parseViewConfig`, `toViewPayload`); `titleFormat`
   existed at none of them. A chosen format would have worked for the current session and silently
   reverted to plain text on the next vault load — invisible to
   `tools/live/render-assertion-harness.ts`, which constructs `ViewConfig` objects directly in
   memory and never exercises this save/load round trip. Confirmed red with a new
   `data-source.test.ts` case (`expected undefined to be 'currency-eur'`), fixed with one
   `parseTitleFormat` helper wired into all four sites.
